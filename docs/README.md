# Документация библиотеки `jwt`

Реализация [JSON Web Token](https://www.rfc-editor.org/rfc/rfc7519) (RFC 7519) для OneScript: подпись и проверка токенов
на алгоритмах семейства HMAC.

## Назначение

Токен переносит утверждения о пользователе между сервисами так, чтобы получатель мог проверить их подлинность сам,
без обращения к базе или к сервису авторизации. Подпись собрана поверх штатного `ХешированиеДанных`, HMAC реализован
по [RFC 2104](https://www.rfc-editor.org/rfc/rfc2104): внешних компонент и нативных библиотек не требуется.

```

|----------------------------------|   |--------------------------------------------|   |----------------|
        заголовок JOSE                              утверждения (claims)                      подпись
```

## Установка

```
opm install jwt
```

Зависимостей времени выполнения нет.

## Быстрый старт

```bsl
#Использовать jwt

// Выпуск: ВремяЖизни в секундах заполняет exp, iat проставляется автоматически
Нагрузка = Новый Структура("sub, role", "user-42", "admin");
Токен = JWT.Подписать(Нагрузка, Секрет, Новый Структура("ВремяЖизни", 3600));

// Проверка: исключений нет, причина отказа возвращается в результате
Результат = JWT.Проверить(Токен, Секрет);

Если Результат.Валиден Тогда
	Роль = Результат.ПолезнаяНагрузка["role"];
Иначе
	Логировать(Результат.КодОшибки, Результат.Ошибка);   // TOKEN_EXPIRED, ...
КонецЕсли;
```

Полезная нагрузка заполняется только для валидного токена: непроверенные данные невозможно использовать по ошибке.

Проверять одну лишь подпись почти всегда мало. Ожидаемые издатель и аудитория задаёт проверяющая сторона:

```bsl
Параметры = Новый Структура();
Параметры.Вставить("Издатель", "oneflag");
Параметры.Вставить("Аудитория", "dashboard");
Параметры.Вставить("Допуск", 30);            // расхождение часов, секунды

Результат = JWT.Проверить(Токен, Секрет, Параметры);
Результат.ВыброситьЕслиНеВалиден();
```

Токен, выпущенный чужой стороной, HMAC не проверить: общего секрета нет. Подпись `RS256` проверяет пакет
[jwt-verify](https://github.com/oscript-library/jwt-verify), а эта библиотека добавляет поверх ожидания
принимающего сервиса и возвращает результат того же вида:

```bsl
#Использовать jwt-verify

Проверяющий = Новый ПроверяющийJWS(Новый КэшJWKS("https://token.actions.githubusercontent.com"));
Результат = JWT.ПроверитьАсимметричный(Токен, Проверяющий, Новый Структура("Аудитория", "https://hub.example.com"));
```

## Примеры

Каждый файл запускается из корня проекта и печатает результат.

```
oscript examples/ВыпускИПроверка.os
oscript examples/ПроверкаУтверждений.os
oscript examples/Отказы.os
```

| Пример | Что показывает |
|---|---|
| `ВыпускИПроверка.os` | Минимальный цикл: подпись, состав токена, проверка, чужой секрет |
| `ПроверкаУтверждений.os` | Издатель, аудитория, сроки, допуск, обязательные утверждения, список алгоритмов |
| `Отказы.os` | Все виды отказов и раскладка кодов на ответы HTTP |
